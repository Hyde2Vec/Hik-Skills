# 产品运营周报

中文产品运营周报 Skill。根据本次材料和要求决定内容，支持产品别名与组成项、多类报告约定、同表持续更新和历史报告重做。默认提供适合手机 OA 阅读的高清长图，以及同内容响应式网页。

**当前状态：试用。** 已验证部分工具和示例，较弱模型仍出现跨口径比较错误和遗漏归档；不能把工具检查通过当作整条业务流程稳定。

## 使用

将本目录安装到所用 Agent 的技能路径后，直接发材料并说：

> 这是本周项目表和 BI，帮我做这周的产品运营周报。

也可以用普通中文调整：

- “管理层那版简短些，项目跟进那版按客户列明细；以后各按这个要求做。”
- “这个产品的出货要合并主机和终端，借用设备不算。”
- “这次只要文字，下次还是原来的样子。”
- “把八月那份重新导出，用当时保存的数据。”

AI 会整理适合复用的约定，已明确要求长期沿用的直接保存；其他建议确认后生效。通用口径与各类报告要求可以放在同一份中文约定中，临时修改只影响当次。各类报告的修订次数和默认比较起点分别管理。

运行规则见 [SKILL.md](SKILL.md)，口径与多类约定写法见 [业务约定示例](references/业务约定示例.md)。

## 环境

优先复用现有工具。附带的文字、CSV、汇总和历史工具只用 Python 标准库；Excel 读取按需使用 openpyxl，网页检查与图片/PDF 导出按需使用 Playwright 和 Chromium。

纯文本主模型可以接收用户授权的多模态服务提取结果；图片识别不使用 OCR，也不绑定特定供应商。图表使用随附的 Apache ECharts，许可证和来源保留在 `assets/vendor/`。

## 验证范围与已知问题

2026-09-03 的验证覆盖了多种表格布局、指标合并、历史工具、三份报告示例的手机/平板/宽屏呈现。多类历史工具已实际验证独立编号、独立起点、重做保留原冻结依据，以及保存不自动移动起点。

另完成了 9 次 `gpt-5.4-mini / low` 任务和 Luna low 使用测试：

- 现成 HTML 首次导出能够完成；明确按需依赖的提示避免了该次多余的 Excel 库安装。
- 普通中文改写保留了金额、日期、否定与条件，临时偏好没有覆盖长期约定。
- 跨周业务任务仍发生把不完整本期金额与完整上期金额直接比较、传入错误比较依据的问题；多类约定能够整理，但未稳定自动完成类型归档。

这些是有限案例，不是通用成功率或真人可用性研究。最后补充的归档命令与完整比较依据说明尚未再次执行完整模型回归；Windows 实机和实际视觉 API 识别也未验证。
