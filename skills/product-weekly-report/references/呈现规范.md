# 呈现规范

把已确认主稿转成 HTML 时的表达规则。样式在 [报告样式.css](../assets/报告样式.css)，组件用法与片段在 [组件示例.html](../assets/组件示例.html)，完整组织方式示例为 示例-逐产品.html、示例-表格专题.html、示例-分析.html。示例是表达示范，不是必须套用的结构。

## 呈现优先级：手机图片优先

- 第一产物是手机 OA 里阅读的 PNG 长图（390 CSS px 阅读宽、3 倍像素密度，不靠把桌面版缩到手机）；HTML 是同一份内容的网页副本。
- 网页响应式：同一份 HTML 与 CSS 在 390/768/1440 等宽度下自然重排——手机纵向可读，≥720px 收成舒适卡片版心，≥1200px 版心放宽、指标组等并列信息网格分栏，正文行长有上限。不用整体缩放冒充响应式。
- 宽度变化只引起重排：内容、重点、阅读顺序与默认可见状态在所有宽度一致，不按宽度隐藏或遗漏任何字段；HTML 在截图所用的手机宽度下与图片有相同的内容和默认可见状态。
- 全部必要内容默认可见：不使用 `details` 折叠，不依赖点击、横向滚动、悬浮 tooltip 才能获得必要信息。内容长就分段呈现，长报告可按用户需要分节交付图片。
- 不为桌面和手机写两份业务内容：一处事实一处写，靠同一套组件自适应，避免两份内容漂移。
- 整体清爽克制：少装饰、少大卡片边框、少空白；标题、正文、数字靠字级和细线分层。

## 基本原则

- 内容决定结构：章节数量、名称、顺序、详略完全按本次主稿，组件清单不反推内容。
- 一个组件表达一类内容，不按产品名或业务名绑定区块；同一组件可以在任何章节出现多次，也可以一次不用。
- 组件可嵌套、可组合：说明区里放列表、章节里连续放指标组＋事件列表＋说明区，都是正常用法。需要新布局时用语义化基础元素（段落、列表、表格、标题层级）组合，不引入样式表之外的机制。
- 数字、单位、日期、状态、否定与条件一律保持来源与主稿原样，不为对齐、美观或行宽改写。缺数写“未提供”，不留空、不按零。

## 从主稿到组件

按主稿内容逐段映射，常用对应关系：

| 主稿内容 | 表达方式 |
| --- | --- |
| 报告标题、周期、范围 | `.report-head` ＋ `.head-meta`；开场段用 `.lead` |
| 一个产品 / 一个专题 / 一组摘要 | `<section>` ＋ `h2.sec`；章节内分块用 `h3.sub` |
| 并列关键数字 | `.metrics` 指标组；单位放 `.unit`，口径放 `.metric-sub` |
| 少列数据（约 2–4 列、文字列可换行） | `.table-wrap` 包 `table`；数字列 `class="num"`（数值与“未提供”不拆行）；口径用 `.caption` |
| 多字段台账 / 原宽表 | `.rows` 键值行列表逐条表达：字段在 `.row-detail` 上加 `.keep-lines` 分行罗列，字段一个不少；不要把多列宽表塞进 390px，也不要删列假装适配 |
| 逐条事件、进展 | `.events` 列表；状态用 `.tag`；来源多行文本加 `.keep-lines` |
| 口径说明 / 风险与待核对 | `.note` / `.note-attention` |
| 长明细、附录、核对依据 | 直接可见：`h3.sub` 小标题＋键值行／少列表展开排 |
| 机读核对数据（如图表 JSON） | 相邻 `<script type="application/json">` 非呈现节点，页面与图片都不显示代码块 |
| 无内容 | `.empty-note` 明示，不留空白章节 |

自由章节（主稿里临时出现的专题、说明段）不需要新组件：一个 `section` 加标题和基础元素即可。

## 事实纪律

- 长产品名、长项目名完整保留，样式会自动换行；不为排版缩短或改写名称。
- 数字保持原写法与原单位；千分位沿用主稿，不自行补零或四舍五入。
- `.tag` 标签只做扫读辅助，条目文字本身仍须完整表达主体、状态、条件与否定。
- “待核对”“未提供”“口径差异”等内容必须可见，不用样式弱化到看不见。
- 图片与网页同一份 HTML：任何“只在网页里有”或“只在图里有”的内容都不允许。

## 图表（可选）

只有本次报告确实需要趋势、对比等图形时才用图表；普通报告不引用图表文件、不增负担。不强制所有报告带图。

- 库文件：`assets/vendor/echarts.min.js`（Apache ECharts 6.1.0 官方发布本地副本，许可证与出处见同目录 `echarts-LICENSE.txt`、`echarts-NOTICE.txt`、`echarts-来源.txt`）。只用本地文件，不联网加载 CDN。
- 主题助手 `assets/图表.js`：与报告样式同一套字体、配色和信息密度，SVG 渲染，图例固定顶部。用法是原生 option，不加包装框架：

```html
<script src="vendor/echarts.min.js"></script>
<script src="图表.js"></script>
<div class="chart" id="chart-1"></div>
<script>
初始化图表(document.getElementById('chart-1'), {
  tooltip: { trigger: 'axis' },
  legend: { data: ['本期', '上期'] },
  xAxis: { type: 'category', data: ['…'] },
  yAxis: { type: 'value', name: '万元' },
  series: [{ name: '本期', type: 'line', data: […] }]
});
</script>
```

- 图表选择按数据形状定：时间趋势用折线（`type: 'line'`），并列对比用柱状（`type: 'bar'`），其他图形用原生 option 直接写。完整示例见 `assets/示例-分析.html`。
- 静态图必须表达完整要点：tooltip、图例开关等交互只是网页上的增强，PNG 里读不到的信息必须同时出现在正文或数据表中。网页与图片的图表默认图例状态一致，导出时自动停动画保证最终态。
- 数据纪律：数据缺失在 series 中写 `null`（图中为断点），不按 0；每张图附近保留同口径、默认可见的人可读数据表；供模型核对的数据 JSON 放相邻的 `<script type="application/json">` 非呈现节点，业务成品不展示原始 JSON 代码块，纯文本模型读该节点即可核对；文字摘要、表格、结构化数据、图形四者数字一致；图表只呈现给定数据，统计计算与因果结论由正文负责。
- 图表一律经 `初始化图表` 创建：视口变化、打印前后的重新适配，以及导出时停动画、等待渲染就绪，都由助手与导出工具自动完成；绕过助手直接 `echarts.init` 的图不受这些保障。
- 打包交付两种都可行：整目录交付时把 `vendor/` 与 `图表.js` 随 HTML 一起复制（保持相对路径引用）；单文件交付时把两个 JS 的内容内联进 `<script>` 标签。交付物中不留本机绝对路径。
- 上下文纪律：`echarts.min.js` 约 1.1MB，不要整份读进对话；写法参考 `图表.js` 和 `示例-分析.html` 就够了。内联单文件时用文件拼接（shell `cat` 或脚本读文件组装 HTML），不在对话里复制库内容。

## 生成后检查点

先用脚本拿到文字化结果，再实际查看页面：

1. 运行 `scripts/检查页面.py`（或导出时自带检查，见下节），默认在手机 390、平板 768、宽屏 1440 三个视口检查。确认 JSON 中无页面错误、资源/图片加载失败、文档水平溢出、元素越界、文字裁切、数值拆行、表格横向溢出、未展开折叠；有问题按输出中的元素路径、文字片段和几何数据定位修正 HTML 后重新运行。
2. 表格横向溢出即失败：说明该表不适配阅读宽，按“少列摘要表＋逐项键值明细”重排，字段保留，而不是继续压缩或加滚动。存在未展开的 `details` 同样计为失败：报告不允许藏明细。
3. 检查 JSON 的“图表”字段中实例数量正确、容器均有渲染内容、无 SVG 文本重叠（如图例与纵轴单位互叠）；图例状态与网页默认一致。
4. 数字列右对齐、数值与“未提供”不被换行拆散（检查脚本对 `td.num` 有基于 Range 几何的自动拆行检测）；缺数显示“未提供”。
5. 与主稿逐条核对：主体、数字、单位、日期、状态、否定、条件一致；图片与网页内容逐项一致。
6. 需要打印时翻页位置合理：标题不孤行、表格行不拦腰断。

## 检查与导出

对已生成的 HTML，`scripts/导出.py` 一次调用同时完成导出与检查（手机 390＋平板 768＋宽屏 1440），检查结果是文字化 JSON，不依赖看图：

```sh
# 导出手机 PNG 长图并同时检查（默认行为：390px 阅读宽、3 倍像素密度）
python <技能目录>/scripts/导出.py <报告.html> --png <输出.png>
# 用户明确需要 PDF 时再生成
python <技能目录>/scripts/导出.py <报告.html> --png <输出.png> --pdf <输出.pdf>
# 已人工确认页面、只需导出时跳过检查
python <技能目录>/scripts/导出.py <报告.html> --png <输出.png> --仅导出
# 只交付 HTML 时仅检查，不导出
python <技能目录>/scripts/检查页面.py <报告.html>
```

纯文本模型流程：生成 HTML → 运行检查/导出并阅读 JSON → 按元素路径与几何数据修正 HTML → 重新运行，直到“检查通过”且所需格式导出成功。导出成功与检查是否通过分开报告：导出失败、检查未通过都会以非零退出并分别说明，已生成的文件保留，两者都满足才算完成。截图供用户或有视觉能力的主控复核，不是必经步骤；检查的覆盖范围与局限印在每次输出的“能力边界”字段中，DOM 检查不等于完整视觉验收。

导出与网页使用同一份 HTML、同一内容、同一默认可见状态：工具不做扩宽画布、不做折叠展开之类的特殊处理——报告本身要求全部内容默认可见并适配阅读宽，不适配的内容由检查失败暴露，交给 Agent 重排。宽度变化只引起自适应重排，网页在 390/768/1440 的内容、重点、阅读顺序与图片一致。检查 JSON 中 `手机图片态` 是截图前的最终几何（PNG 行同时报告布局宽与像素宽×高，便于核对）；`平板`/`宽屏` 两个视口验证响应式重排无越界、无拆行、无溢出；`PDF打印态` 在 print 媒体模拟、视口固定为 A4 内容宽 688px（对应样式表 `@page` 的 16mm/14mm 边距；若改边距须同步 `导出.py` 中的 `PDF内容宽`）下执行，图表先在该宽度重新适配并完成渲染，再检查、再生成——它是与 A4 内容等宽的近似几何检查，不逐页核对分页效果，分页以实际 PDF 为准。停动画标记（`__REPORT_STATIC_EXPORT__`）与导出态判定（`__REPORT_EXPANDED_EXPORT__`）是两个标记；`.chart` 容器存在但没有任何实例初始化会报告，图表渲染等待失败会原样记入 `图表等待` 与 `图表等待警告`，并在任何模式（含 `--仅导出`）下使本次调用以失败返回，已生成的文件保留供检查。

两个脚本的共同约定：只处理已有 HTML，不生成或改写正文；渲染前等待字体与图表就绪；检查 JSON 的“图表”字段报告实例数量、容器尺寸与是否有实际渲染内容（不作美观断言）。导出目标已存在会拒绝覆盖；部分格式失败会明确说明哪些成功、哪些失败。若需独立单文件 HTML，交付时将 CSS 与所需 JS 内联进 `<style>`/`<script>` 标签即可，样式表与图表库均无外部依赖。
